# BabyLink Client – לקוח React

לקוח React ל-[BabyLink API](https://github.com/BrachaBeker/BabyLinkAPI): הורה מפרסם בקשת שמרטפות, שמרטפיות מסננות, ו**הראשונה שתופסת זוכה**. השנייה מקבלת **409**, והלקוח מציג לה את זה בבירור.

🔗 [לקוח](https://babylinkclient.onrender.com) · [שרת](https://babylink-api.onrender.com) · [Swagger](https://babylink-api.onrender.com/swagger) · [Repository השרת](https://github.com/BrachaBeker/BabyLinkAPI)

## המסכים
| מסך | מה יש בו |
|---|---|
| התחברות והרשמה `/login` | בחירת תפקיד (להורה גם כתובת בית), שגיאות מהשרת ליד כל שדה, כפתורי מילוי למשתמשי הדמו |
| רשימת בקשות `/requests` | **שמרטפית:** "פנויות" ו"השיבוצים שלי" (עם לוח השבוע הקרוב), סינון ומיון. **הורה:** רק הבקשות שלו, בלשוניות ממתינות / נמצאה שמרטפית / היסטוריה. Pagination |
| פרטי בקשה `/requests/:id` | **שמרטפית:** "אני לוקחת", וביטול שיבוץ עד 24 שעות לפני המועד. אחר כך הכפתור חסום ועליה להשיג מחליפה, ועל בקשה שמתחילה בעוד פחות מ-24 שעות היא מוזהרת כבר לפני התפיסה. **הורה:** פרטי השמרטפית שתפסה, עריכה (כל עוד לא נתפסה), ביטול גם אחרי שנתפסה, ביטול ופרסום מחדש, ופרסום שוב מההיסטוריה |
| טופס בקשה `/requests/new`, `/requests/:id/edit` | אותו טופס ליצירה ולעריכה. בבקשה חדשה הכתובת ממולאת מהפרופיל |
| הפרופיל שלי `/profile` | שם, טלפון, עיר וכתובת |

**פעמון הודעות:** "נמצאה שמרטפית!" ו"השמרטפית ביטלה את השיבוץ" להורה (עם קישור לבקשה), ו"בקשה שתפסת בוטלה" לשמרטפית. בכניסה הרשימה נפתחת לבד, והודעה חדשה מנענעת את הפעמון.

## תרחיש ה-409
1. שני דפדפנים (או חלון רגיל וחלון בסתר) עם `sitter1@babylink.dev` ו-`sitter2@babylink.dev`, באותה בקשה **פנויה**.
2. בראשון "אני לוקחת" ← הודעה ירוקה, והסטטוס מתחלף ל"נתפסה".
3. **מיד** אחר כך (תוך 10 שניות, לפני העדכון החי) "אני לוקחת" בשני ← **409**: הודעה אדומה "הבקשה כבר נתפסה על ידי שמרטפית אחרת.", והבקשה נטענת מחדש כ"נתפסה", בלי שם השמרטפית.
4. אם בשני מחכים, המסך מתחלף לבד ל"הבקשה נתפסה הרגע". כשהשמרטפית שתפסה מבטלת, מופיע "הבקשה התפנתה".

## החלטות
- **React 19 + Vite + TypeScript** ו-`react-router-dom`. בלי ספריית UI: CSS רגיל, `lucide-react` וגופן Heebo. עברית ו-RTL.
- **שכבת API אחת** (`src/api/client.ts`): `apiRequest` מוסיפה את כתובת השרת ואת ה-JWT, ומתרגמת כל ProblemDetails ל-`ApiError`. 401 ← ניתוק ומעבר להתחברות.
- **הרשאות ופרטיות נאכפות בשרת.** הלקוח רק מחליט מה להציג. את פרטי השמרטפית שתפסה השרת מחזיר רק להורה ולה עצמה, והלקוח מציג אותם רק להורה.
- **עדכון חי ב-Polling** (`usePolling`): כל 10 שניות (בפעמון 15), רק בטאב גלוי. תשובה שמגיעה אחרי פעולה של המשתמש לא דורסת אותה. Polling ולא SignalR: פשוט, ועובד גם מאחורי Proxy. הוא מצמצם התנגשויות, אבל ה-409 בשרת הוא ההגנה האמיתית.
- **זמנים:** השרת ב-UTC, והלקוח ממיר לשעון המקומי ובחזרה. **ולידציה** בטפסים לנוחות בלבד; השרת הקובע.
- **הלשוניות והסינון נשמרים ב-URL**, כך שרענון או חזרה שומרים על המצב. **שרת שנרדם:** אחרי כמה שניות מוצג הסבר שהוא "מתעורר".
- **מבנה:** `src/api` (קריאות לשרת וחוזה ה-API), `auth`, `components`, `hooks`, `pages` (auth, requests, details, form, profile), `utils`.

## הרצה מקומית
דרישות: Node.js 20 ומעלה, והשרת רץ על `http://localhost:5083` (ראו ה-README של השרת).
```bash
npm install
cp .env.example .env    # VITE_API_URL=http://localhost:5083
npm run dev             # http://localhost:5173 (השרת מאפשר CORS רק לפורט הזה)
```
**משתמשי דמו** (סיסמה `Demo123!`): `parent1@babylink.dev`, `parent2@babylink.dev`, `sitter1@babylink.dev`, `sitter2@babylink.dev`.

## פריסה (Render Static Site)
- Build: `npm install && npm run build` · Publish: `dist` · Environment: `VITE_API_URL=https://babylink-api.onrender.com`.
- **Rewrite** מ-`/*` ל-`/index.html`, אחרת F5 בעמוד פנימי מחזיר 404. בשרת: `Cors__AllowedOrigins__0` עם כתובת הלקוח, בלי `/` בסוף.
