# BabyLink Client – לקוח React

לקוח React שמדגים את [BabyLink API](https://github.com/BrachaBeker/BabyLinkAPI): Web API ב-.NET 10 לתיווך בין הורים לשמרטפיות. הורה מפרסם בקשת שמרטפות, שמרטפיות רואות ומסננות את הבקשות, ו**הראשונה שתופסת בקשה זוכה בה**. השנייה מקבלת **409 Conflict**, והלקוח מציג לה את זה בצורה ברורה.

> 🔗 לקוח: https://babylinkclient.onrender.com · שרת: https://babylink-api.onrender.com · Swagger: https://babylink-api.onrender.com/swagger · Repository השרת: https://github.com/BrachaBeker/BabyLinkAPI

## המסכים

|---|---|---|---|
| 1 | התחברות והרשמה | `/login` | התחברות, הרשמה עם בחירת תפקיד (הורה / שמרטפית) - להורה גם כתובת בית, שגיאות מהשרת ליד כל שדה, כפתורי מילוי מהיר למשתמשי הדמו. אחרי התחברות תמיד מגיעים לרשימת הבקשות |
| 2 | רשימת בקשות | `/requests` | כרטיסים עם מועד (בשעון מקומי), כתובת, ילדים, תעריף, תגיות וסטטוס. **שמרטפית:** לשוניות **פנויות** (ברירת מחדל) ו**השיבוצים שלי** - עם **לוח השבוע הקרוב** מתחת לכרטיסים ו"הצג עוד" לכל הלוח; סינון (עיר, רחוב, תגית, תעריף מינימלי) ומיון. **הורה:** רק הבקשות שלו, בלשוניות **ממתינות לשמרטפית**, **נמצאה שמרטפית** ו**היסטוריה**. Pagination |
| 3 | פרטי בקשה | `/requests/:id` | כל הפרטים, סה"כ לבקשה (תעריף × שעות), ההורה והשמרטפית שתפסה. שם וטלפון השמרטפית גלויים רק להורה שפרסם ולשמרטפית עצמה; כל השאר רואים רק מתי הבקשה נתפסה. שמרטפית: **"אני לוקחת"**, ו**ביטול השיבוץ** עד 24 שעות לפני המועד (ההורה מקבל הודעה); פחות מזה הכפתור חסום, ומוצגת הודעה שעליה להשיג מחליפה. על בקשה שמתחילה בעוד פחות מ-24 שעות מוצגת אזהרה כבר לפני "אני לוקחת". ההורה: עריכה (כל עוד לא נתפסה), **ביטול** - גם אחרי שנתפסה, כי הוא לא מחויב לשמרטפית - **ביטול ופרסום מחדש**, ו**פרסום שוב** של בקשה מההיסטוריה |
| 4 | טופס בקשה (הורה) | `/requests/new`, `/requests/:id/edit` | אותו טופס ליצירה (POST) ולעריכה (PUT). בבקשה חדשה הכתובת ממולאת מראש מהפרופיל |
| + | הפרופיל שלי | `/profile` | עדכון שם, טלפון, עיר וכתובת (לחיצה על השם בסרגל העליון) |

**פעמון הודעות** בסרגל העליון:

| הודעה | מתי | למי |
|---|---|---|
| נמצאה שמרטפית! | שמרטפית תפסה בקשה | להורה (עם קישור לבקשה) |
| השמרטפית ביטלה את השיבוץ | השמרטפית ביטלה, והבקשה חזרה להמתין | להורה (עם קישור לבקשה) |
| בקשה שתפסת בוטלה | ההורה ביטל בקשה שכבר נתפסה | לשמרטפית |

בכניסה למערכת, אם יש הודעות, הרשימה נפתחת לבד. הודעה שמגיעה תוך כדי עבודה מנענעת את הפעמון.

**עדכון חי:** הרשימה, לוח השבוע, מסך הפרטים והפעמון מתעדכנים לבד - בקשה שנתפסה מתחלפת ל"נתפסה", בקשה חדשה מופיעה, וההורה רואה מיד שנמצאה שמרטפית. הטופס והפרופיל לא מתרעננים, כדי לא לדרוס את מה שמקלידים.

## תרחיש ה-409 (הלב של הפרויקט)

1. פותחים שני דפדפנים (או חלון רגיל + חלון גלישה בסתר).
2. בראשון מתחברים כ-`sitter1@babylink.dev`, בשני כ-`sitter2@babylink.dev`.
3. בשניהם נכנסים לאותה בקשה **פנויה**.
4. בראשון לוחצים **"אני לוקחת"** ← הודעת הצלחה ירוקה, והסטטוס מתחלף ל"נתפסה".
5. **מיד** אחר כך (תוך פחות מ-10 שניות - לפני שהעדכון החי מגיע), בשני לוחצים **"אני לוקחת"** ← השרת מחזיר **409**, ומופיעה הודעה אדומה ובולטת: *"הבקשה כבר נתפסה על ידי שמרטפית אחרת."* הלקוח **טוען מחדש את הבקשה מהשרת**, והמסך מראה "נתפסה" ומתי - בלי שם השמרטפית שתפסה (פרטיות).
6. אם בשני מחכים, המסך מתחלף לבד: *"הבקשה נתפסה הרגע - שמרטפית אחרת תפסה את הבקשה הזו."*

גם תרחיש הפוך עובד: אם השמרטפית שתפסה מבטלת את השיבוץ, אצל השנייה מופיע *"הבקשה התפנתה"* וכפתור "אני לוקחת" חוזר.

## טכנולוגיות והחלטות

- **React 19 + Vite + TypeScript**, ניווט עם `react-router-dom`.
- **בלי ספריית UI:** מערכת עיצוב קטנה ב-CSS רגיל (משתנים ב-`src/index.css` וקובץ CSS לכל מסך). אייקונים מ-`lucide-react`, גופן Heebo.
- **עברית ו-RTL** (`<html lang="he" dir="rtl">`).
- **שכבת API אחת** (`src/api`): כל קריאה עוברת דרך `apiRequest`, שמוסיפה את כתובת השרת, את ה-JWT ואת ה-headers, ומתרגמת כל שגיאה (ProblemDetails) ל-`ApiError` אחיד.
- **JWT:** אחרי ההתחברות ה-token נשמר ב-`localStorage`, ונשלח בכל בקשה כ-`Authorization: Bearer <token>`. כשהשרת מחזיר **401** הלקוח מוחק את ה-token ומעביר למסך ההתחברות.
- **הרשאות נאכפות בשרת:** הלקוח משתמש בתפקיד רק כדי להחליט מה להציג (למשל להסתיר את "בקשה חדשה" משמרטפית). גם אם מישהו "יעקוף" את הלקוח, השרת יחזיר 403.
- **זמנים:** השרת עובד ב-UTC. בשליחה ממירים זמן מקומי ל-UTC (`new Date(local).toISOString()`), ובהצגה ממירים חזרה לשעון המקומי.
- **שרת שנרדם:** השרת החינמי ב-Render נרדם אחרי זמן ללא שימוש, והבקשה הראשונה לוקחת עד כדקה. כל בקשה מציגה מצב טעינה, ואחרי כמה שניות מופיע הסבר שהשרת "מתעורר".
- **ולידציה:** הטפסים בודקים מראש את הכללים הבסיסיים (שדות חובה, סיום אחרי התחלה, התחלה בעתיד, עד 24 שעות) לנוחות המשתמש. השרת בודק שוב והוא הקובע. הודעות הוולידציה האוטומטיות של ASP.NET חוזרות באנגלית, ולכן הלקוח מתרגם את התבניות המוכרות לעברית.
- **עדכון חי ב-Polling** (`src/hooks/usePolling.ts`): כל 10 שניות (בפעמון - 15) הלקוח טוען שוב בשקט את מה שעל המסך, ומעדכן רק אם משהו השתנה. תשובה שיצאה לפני פעולה של המשתמש (תפיסה, ביטול שיבוץ, סגירת הודעה) ומגיעה אחריה כבר ישנה, ולכן לא דורסת את התוצאה. טאב ברקע לא שולח בקשות, וכשחוזרים אליו הוא מתרענן מיד. בחרנו ב-Polling ולא ב-Push (SignalR) כי הוא פשוט, לא דורש טכנולוגיה נוספת בשרת, ועובד גם מאחורי סינון ו-Proxy. **חשוב:** עדכון חי מצמצם התנגשויות אבל לא מבטל אותן - תמיד יש חלון זמן שבו שתי שמרטפיות רואות "פנויה". לכן ה-409 של השרת (Optimistic Concurrency) נשאר ההגנה האמיתית.
- **נראות ופרטיות (נאכף בשרת):** הורה רואה רק את הבקשות שלו. מי תפסה בקשה (שם וטלפון) רואים רק ההורה שפרסם והשמרטפית עצמה - לשאר השרת מחזיר את השדות האלה ריקים, והלקוח מציג במקומם "פרטים חסויים" ומתי הבקשה נתפסה. כברירת מחדל מוצגות רק בקשות עתידיות.
- **הלשוניות והסינון נשמרים ב-URL** (למשל `/requests?view=mine&city=ירושלים&page=2`), כך שרענון או חזרה ממסך הפרטים שומרים על אותו מצב.
- **"פרסום מחדש":** פרטי הבקשה עוברים לטופס ב-state של הניווט. בקשה מההיסטוריה מקבלת אותו יום ושעה בשבוע הקרוב.

## הרצה מקומית

דרישות: Node.js 20 ומעלה, והשרת רץ מקומית על `http://localhost:5083` (ראו ה-README של השרת).

```bash
npm install
cp .env.example .env    # ב-PowerShell: Copy-Item .env.example .env
npm run dev             # http://localhost:5173
```

> השרת מאפשר CORS ל-`http://localhost:5173` (פורט ברירת המחדל של Vite), לכן לא משנים את הפורט.

פקודות נוספות: `npm run build` (בנייה ל-`dist`), `npm run preview` (הרצת ה-build).

## פריסה ב-Render (Static Site)

1. **New ← Static Site**, ובוחרים את ה-repository `BabyLinkClient`.
2. **Build Command:** `npm install && npm run build`
3. **Publish Directory:** `dist`
4. **Environment:** `VITE_API_URL=https://babylink-api.onrender.com`
5. **Redirects/Rewrites:** Source `/*` ← Destination `/index.html`, Action **Rewrite**. בלי זה, רענון בעמוד פנימי (למשל `/requests/5`) יחזיר 404.
6. **בשרת** (ה-Web Service `babylink-api`) מוסיפים משתנה סביבה `Cors__AllowedOrigins__0` עם הכתובת של ה-Static Site, בלי `/` בסוף, ועושים Deploy מחדש לשרת.
